# SAPolicy + YAM

## Current deployment

MV51 RAW connects through `XPolicyLab/policy/SAPolicy` and shared `xpolicylab_ws`.
Model source, dependency installation, data, and training entry points reside in that policy directory. ManiMux owns cameras,
observation mapping, YAM FK/IK, scheduling, execution, and recording. For installation and resources, see
[SAPolicy README](../../../../../XPolicyLab/policy/SAPolicy/README.md).

Supports `yam_dual / ee`. The model returns a standard action dictionary: absolute end-effector poses for both arms use
`[x,y,z,qw,qx,qy,qz]`, with continuous gripper opening from 0 closed to 1 open. The YAM adapter converts these into
two 7D joint targets. The legacy xyzw `packed_ee_wire` format remains explicitly selectable,
sharing inference and execution semantics with the standard interface.

| Parameter | MV51 RAW setting |
| --- | --- |
| checkpoint | `ft_teleopMV51_from_abc_notcpkv_rot5_bs1024_raw.ckpt` |
| Weights | RAW, `use_ema: false` |
| Observation history | One frame, external view + both wrists |
| action horizon / sampler steps | 50 / 10 |
| Ordinary chunk execution prefix | The still-valid portion of the first 25 source timesteps |
| RTC | Horizon 50; minimum execution 25; initial delay 4; delay window 10; beta 5 |
| Smoother | Shared `SmoothExecutor`, `tracking_mode: legacy`, 8 Hz low-pass filter |
| Model action interval / control frequency | 1/30 s / 100 Hz |
| Joint velocity / acceleration limits | Both disabled (explicit `null`) |
| Grasp / release waiting state machine | Disabled in current low-pass and RTC configurations |
| Gripper velocity / acceleration / separate closing-speed limit | All disabled (explicit `null`) |
| TCP reference | Training MJCF grasp_site, additional offset = 0 |
| Images | RGB; 640×480 → 224×168, model center crop 210×154 |

For each execution mode, the three infrastructure configurations differ only in external camera, view identifier, and recording directory. The model SHA-256 is
verified at startup and used by runtime to match backend identity, replacing machine-specific absolute weight paths as identity.
Old teleop50 / ABC configurations remain for historical compatibility and are not MV51 entry points.

All six ordinary/RTC MV51 configurations explicitly disable software rate limits; deleting those fields restores default limits.
Position bounds remain independent. The low-pass smoother uses continuous grippers without the original braking grasp/release wait.
The shared YAM configuration still includes
a separate gripper closing-speed limit, so these configurations explicitly supply the complete unrestricted MV51 settings.
Restart `manimux serve` after changes to load the new values.

## Installation and model service

Run from the ManiMux root. First follow the policy README to build `checkpoints/finetuned/sapolicy/teleopMV51/`
from the original model weights, DINOv2 weights, and matching normalizer.
Model weights and local recordings are excluded from Git.

```bash
bash XPolicyLab/policy/SAPolicy/install.sh
XPolicyLab/policy/SAPolicy/.venv/bin/python manimux/servers/sapolicy.py \
  --config manimux/configs/policy/sapolicy/yam/teleopMV51/raw.yaml --check
XPolicyLab/policy/SAPolicy/.venv/bin/python manimux/servers/sapolicy.py \
  --config manimux/configs/policy/sapolicy/yam/teleopMV51/raw.yaml
```

`--check` validates configuration and resources only. The shared model service defaults to `ws://127.0.0.1:8510`
and does not connect to hardware. It uses the resolved recipe in the policy directory, independent of external source trees or
YAML generated by a particular experiment.

| View configuration | External camera | Wrist cameras |
| --- | --- | --- |
| `top.yaml` | `d405_front`, RealSense Top | `d405_left`, `d405_right` |
| `gemini305.yaml` | Gemini305, serial `CV278640000Z` | Same as above |
| `gemini335.yaml` | Gemini335, serial `CP0N763000LK` | Same as above |

Gemini UVC RGB nodes are located by device serial number. Each run requests and checks only the selected three cameras.
GUI defaults to `camera_mode: policy`, following `policy.adapter.camera_map` reported by runtime.
The main view displays its model input name; smaller wrist views use `left side` / `right side` labels.
The complete model-input-to-physical-camera mapping appears in the table on the right.
The model configuration declares input views, deployment binds local cameras, and RoboGUI displays them automatically without duplicate bindings.
Inputs follow mapping order: the first is the main view, and the Top overlay follows it.
Inputs beyond the first three appear under the additional input cameras section.
Without a model input configuration, the GUI shows default `top / left / right` previews with a configuration-not-received notice.
New runs, runtime changes, disconnection, and view changes clear stale images; missing selected views show a waiting-for-image message.

For debugging, use `--config manimux/configs/robogui/yam-top.yaml`, `yam-gemini305.yaml`, or
`yam-gemini335.yaml` (the latter two also under `manimux/configs/robogui/`) for `camera_mode: manual`.
This overrides previews only. The UI still lists model inputs; preview selection does not change images sent to the model.
To restore automatic following, omit RoboGUI `--config` or explicitly set `camera_mode: policy`.
Recordings retain physical camera names and `view_profile`.

## Rollout

```bash
envs/yam/.venv/bin/manimux serve \
  --config manimux/configs/experiments/put_bottles/sapolicy/yam_sapolicy_mv51_top.yaml
# For RTC: stop the previous runtime, then select this configuration
envs/yam/.venv/bin/manimux serve \
  --config manimux/configs/experiments/put_bottles/sapolicy/yam_sapolicy_mv51_top_rtc.yaml
```

Open `http://localhost:8086`, click **Prepare normal rollout**, arrange the scene, then
click **Start rollout**. **Pause / Hold** pauses; **Finish & Home** saves the run and
homes both arms simultaneously under the current configuration (5 seconds). Finish the run and stop its runtime before changing views,
then start the next run with `yam_sapolicy_mv51_gemini305.yaml` or `yam_sapolicy_mv51_gemini335.yaml`. In default mode the GUI follows automatically
without a restart; camera and model services can be reused.
RTC uses `yam_sapolicy_mv51_gemini305_rtc.yaml` and `yam_sapolicy_mv51_gemini335_rtc.yaml` with the same model service.
Runtime starts only when the backend implements and declares `rtc`; identity checks remain enabled.

Recordings live in `data/sapolicy/teleopMV51/<view>/session-*/rollout-*`; RTC views have the `-rtc` suffix.
`result.run_completed` means only that the run completed; bottle-deposit success requires observation or manual evaluation.
Current execution uses process-based IK, paired dual-arm submission, and low-pass smoothing. Independent arm submission depends on braking
and is not used by these configurations. RTC applies same-frame FK to the old joint trajectory, then converts it into relative
actions and normalizes them in SA; the actual DiT sampler performs VJP guidance. Ordinary chunk transitions blend four steps.
RTC also blends four steps initially, but does not add blending to subsequent conditioned chunks.
The 25 RTC steps are a scheduling minimum, not a fixed removal of the second half; scheduling adapts to measured inference and decoding latency.
Historical braking recordings do not validate the new smoother/RTC on hardware.

## tcp_rot20: ABC bottles zero-shot

`tcp_rot20` is a training-provider checkpoint for dual-arm, three-camera TCP bottle placement (RAW, step 50k),
without fine-tuning on this station's data.

### Resource bundle

`checkpoints/finetuned/sapolicy/tcp_rot20/` is excluded from Git. Copy it between machines with `rsync -aL`
(`-L` dereferences local symlinks):

| File | Contents |
| --- | --- |
| `model.ckpt` | Training checkpoint, `sha256:d84e94f2…b032825a3f` (full value in configuration, verified at service startup) |
| `backbone.pth` | DINOv2 initialization weights (same as teleopMV51), subsequently overwritten by strict checkpoint loading |
| `action_normalizer.pt` | Action normalization matching the checkpoint |
| `resolved_config.yaml` | Resolved training configuration |
| `resolved_config.compiled.yaml` | Same, with `compile_backbone` / `compile_action_head` enabled |
| `source/` | SpatialAlignVLA rollsweep0917 source snapshot with an inference-time RTC patch; ordinary sampling is bitwise identical to the original |

```bash
rsync -aL --info=progress2 <source-host>:~/manimux/checkpoints/finetuned/sapolicy/tcp_rot20/ \
  checkpoints/finetuned/sapolicy/tcp_rot20/
```

### Startup

```bash
XPolicyLab/policy/SAPolicy/.venv/bin/python manimux/servers/sapolicy.py \
  --config manimux/configs/policy/sapolicy/yam/tcp_rot20/raw-50k.yaml
envs/yam/.venv/bin/manimux serve \
  --config manimux/configs/experiments/put_bottles/sapolicy/yam_sapolicy_tcp_rot20_async40_cranksite.yaml
```

Server inference takes about 60–90 ms on a 4090 without compilation. For faster inference, change `cfg_file` to
`resolved_config.compiled.yaml` and set `TORCH_ALLOW_TF32_CUBLAS_OVERRIDE=1` (approximately 36 ms).
Initial requests compile for several minutes; warm up with requests before starting a rollout.

### Settings and rationale

| Item | Setting | Reason |
| --- | --- | --- |
| Scheduling | ManiMux async, execute 40/50 steps per chunk, blend 4, refill 0.2 s | obs_hist=1; descent is in the latter half of each chunk, so executing only 16–25 steps causes persistent hovering |
| IK decoding | `action_decoding: process` | Control-thread IK stalls each handover for 30–100 ms, causing arm shaking |
| Executor | Smooth braking, 0.6 rad/s, 1.5 rad/s² | Measured `yam_smooth_braking.yaml` values; high-frequency jitter 2.4 → 1.05 °/s |
| Gripper | Continuous, no rate limit or guard | — |
| Initial pose | Median ABC-130k bottles ready pose, 4 s | ABC data contains no episodes starting from zero pose |
| Mounting height | `model_from_kinematics` z +2.2 cm | Local base plate is 2.2 cm, verified from J2 axis height and zero-pose fingertip height |
| TCP reference | `tcp_rot20/crank_site_assets`: linear_4310 grasp_site shifted −4.1 cm along site x | About 59% of ABC uses crank_4310, whose fingertip is offset 4.1 cm from grasp_site; only one site changes, meshes symlink to default assets |

### Known behavior

- Test-time RTC is ineffective: denoiser input sensitivity ∂x̂/∂x is only approximately 0.01–0.06.
- Repeated requests on the same observation near the ABC ready pose differ by 0.5–3.5 cm over the first 16 rows and 3–10 cm at the chunk end.
  The backend has no `inference_seed`.
- Fingertip height at grasp closure barely changes with z offsets or crank correction; final approach is visually driven.
  The remaining discrepancy comes from the model's interpretation of this station's images and cannot be resolved by mounting compensation.

## Offline validation

### Using other SAPolicy training checkpoints

For each checkpoint, configure `model_path`, its resolved training `cfg_file`, matching
`normalizer_path`, `backbone_path`, and `checkpoint_source`. To match a training source snapshot,
point `sapolicy_root` to it. The adapter retains its normalization and TCP pose wrappers,
importing only the model core from that snapshot. Changing source snapshots requires a new model process.

Joint TCP + action training may use nested `dataset_opts` lists. The adapter uses
`combined_loader_opts` to select the final action branch, checks that all its datasets agree on action semantics,
image preprocessing, and camera order, then uses it for inference. Strict weight loading rejects missing or extra parameters.
Old training snapshots without RTC declare only ordinary sampling and cannot directly use MV51 RTC experiments.

The following commands still use MV51 as an example; substitute the new checkpoint's own configuration and weight paths.

```bash
envs/yam/.venv/bin/python -m pytest -o addopts='' -q \
  XPolicyLab/policy/SAPolicy/tests tests/unit/test_sapolicy_xpl_model.py \
  tests/unit/test_sapolicy_xpl_transport.py tests/unit/test_sapolicy_decode_timing.py
XPolicyLab/policy/SAPolicy/.venv/bin/python -m pytest -o addopts='' -q \
  XPolicyLab/policy/SAPolicy/tests
XPolicyLab/policy/SAPolicy/.venv/bin/python -m XPolicyLab.policy.SAPolicy.validate_checkpoint \
  --model-config manimux/configs/policy/sapolicy/yam/teleopMV51/raw.yaml \
  --checkpoint "$PWD/checkpoints/finetuned/sapolicy/teleopMV51" --rtc \
  --output data/sapolicy/checkpoint-validation.json
envs/yam/.venv/bin/python scripts/validation/xpolicylab_yam_forward_probe.py \
  --config manimux/configs/experiments/put_bottles/sapolicy/yam_sapolicy_mv51_top_rtc.yaml
```

The final command requires the model service and sends only synthetic images and configured joint states; it opens no cameras and controls
no robot. See the policy README for standard debug, encoded images, batching, native data processing, and training entry points.

Validation on 2026-09-13 covered a fresh environment installation, actual GPU forward inference, numerical equivalence between standard and legacy
action formats, the shared server, offline YAM IK, batch/reset, native ABC reading, and
one GPU training step with checkpoint saving on synthetic data. After the standard-interface migration, one Top hardware rollout was
ended and saved by the operator; it still used old speed limits and had no task-success annotation.

Subsequent offline smoother/RTC validation reduced overlap error for three fixed seeds with real weights.
Zero-weight RTC was value-identical to ordinary sampling; reset and condition clearing passed. Shared debug with ordinary images,
encoded-image batches, and RTC → YAM IK for all three views passed. With synthetic observations, RTC forward inference took
approximately 172–183 ms and warm requests plus dual-arm IK about 310 ms. The new smoother/RTC had not yet run a hardware rollout in this record.
